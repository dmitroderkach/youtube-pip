# Internationalization

Every user-facing text of the userscript goes through `src/i18n`, in the language of the YouTube interface. Today that is one text: YouTube's name of picture-in-picture, the label of our PiP entry points (context menu items, PiP buttons, the button tooltip; `PiPEntryPoints`).

## Texts are YouTube's own

We never write our own wording for a UI text YouTube already has. `PIP` in every language is the tooltip of YouTube's own PiP button, taken from the localized player bundle (`/s/player/<version>/player_es6.vflset/<locale>/base.js`, the `data-tooltip-title` of the PiP button: `"Exit picture-in-picture" : "Picture-in-picture"`). It is the same text YouTube shows on its own PiP button and context menu item (`web_watch_pip*`), so ours read exactly like YouTube's.

## Structure

- `messages.ts`: the message keys and the English dictionary (`EN_MESSAGES`), the reference: its keys are the type every dictionary must satisfy (`Messages`), and the fallback.
- `dictionaries.ts`: one dictionary per YouTube interface language, keyed by YouTube's `hl` code: the 83 languages of YouTube's language picker (`youtubei/v1/account/account_menu`), e.g. `uk`, `pt-PT`, `sr-Latn`, `zh-TW`, `iw`, `no`.
- `I18n.ts`: injectable `I18n` service, `t(key)` and `getLanguage()`. The language is resolved once, on first use (YouTube reloads the page when the user changes its language):
  - YouTube's `hl` from `ytcfg` (`HL`), else `<html lang>` (`uk-UA`, `zh-Hant-TW`, `he-IL`, `nb-NO`);
  - `resolveLanguage()`: the exact code, then language + script / region (`sr-Latn-RS` → `sr-Latn`, `zh-Hant-TW` → `zh-TW`), then the language alone (`uk-UA` → `uk`); `he` → `iw`, `nb` → `no`; English otherwise.
- Tests (`src/i18n/__tests__/I18n.test.ts`): a dictionary for every YouTube language and no other, every key filled in every dictionary, English equal to the reference, language resolution for codes and `<html lang>` tags, the `ytcfg` / `<html lang>` order.

## Adding a text

1. Add the key with its English text to `EN_MESSAGES`.
2. Add it to every dictionary in `dictionaries.ts` (the type check fails otherwise). Take the text from YouTube's own localized strings (player bundle or Kevlar) when YouTube has it; a text of our own needs a native check.
3. Use `i18n.t('KEY')` in the component (inject `I18n`); no literal UI strings in components.

## Updating the dictionaries

When YouTube adds a language or changes its PiP name: list the languages from `account_menu` (`hl` values), read each language's player locale from `/embed/<id>?hl=<hl>` (`jsUrl`), and extract the ternary before `this.update({"data-tooltip-title":a` from that locale's `base.js` (string literals may use single or double quotes and `\\uXXXX` escapes).
