# Internationalization (planned)

Status: **not implemented**. The only user-facing texts of the userscript today are the labels of the PiP entry points in the player (context menu item, controls button, `ENTRY_POINT_LABELS` in `src/constants/ui.ts`, added in 2.7.0). They are in Ukrainian only, whatever the language of the YouTube page: the feature is an experiment. This page records how to add languages once more texts appear or the experiment stays.

## Goal

- Every user-facing text of the userscript goes through one module; no literal UI strings in components.
- A language is a dictionary file; adding one needs no code change elsewhere.
- The text follows the language of the YouTube page, with English as the fallback.

## Design

- **Keys and dictionaries**: `src/i18n/messages.ts` defines the message keys and the English dictionary (`en`), which is the reference: its type is the type every other dictionary must satisfy (`Record<MessageKey, string>`), so a missing key in a translation fails the type check. Other languages live next to it (`src/i18n/uk.ts`, `pl.ts`, …) and may be partial (`Partial<…>`); a missing key falls back to English.
- **Language detection**: the page language from YouTube itself: `document.documentElement.lang` (e.g. `uk-UA`), or `ytcfg.get('HL')` when it is missing. Match the full tag first (`pt-BR`), then the base language (`pt`), then `en`. Read once at start; YouTube reloads the page when the user changes the interface language.
- **API**: an injectable `I18n` service (DI container like the other services) with `t(key, params?)`; `params` fill `{name}` placeholders. Components get it injected instead of importing constants with texts.
- **PiP window**: texts are created in the main document and moved with the player, so nothing changes for PiP.
- **Tests**: unit tests for detection (full tag, base language, fallback) and for missing keys; one check that every dictionary has only known keys. E2E keeps matching our elements by class, not by text, except where a test pins the label of one language (it then sets the page language).

## Migration

1. Add the module with `en` and `uk` dictionaries holding today's `ENTRY_POINT_LABELS`.
2. `PiPEntryPoints` takes the labels from `I18n`; remove `ENTRY_POINT_LABELS`.
3. New UI texts are added only as message keys.
